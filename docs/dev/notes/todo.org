- [X] LSP `K` (hover): popup doesn't appear on first press; requires
  an additional key press, and is not positioned at the cursor
  location. Two GPUI fixes (2026-05-27):
  - Wake-bridge in ~EditorView::new~ now drains ~run_tick_pending~
    before ~cx.notify()~ so idle LSP arrivals (hover, signature
    help, …) materialize without the next keystroke.
  - ~Editor::pending_hover_anchor~ stashes ~(cursor, scroll)~ at
    K-press; ~open_floating_popup~ consumes it one-shot so the
    popup pins to the invocation site rather than wherever the
    cursor drifted to between K and the LSP response.
  - Popup body now renders every row through a uniform
    ~flex_row~ of per-char divs (previously non-cursor lines
    used naked text, cursor line used per-char flex — metrics
    diverged, current line jumped a char right on every motion).
- [X] Popup buffers don't scroll when the cursor moves past the
  viewport (GPUI only — TUI was fine). Per-frame override on the
  GPUI render pass sets ~Editor::viewport_height~ to the popup's
  inner row count (~POPUP_INNER_HEIGHT_ROWS = 30~) while focused
  so ~ensure_cursor_in_viewport~ scrolls correctly; restores from
  the active leaf when the popup is dismissed.
- [X] `describe-buffer`'s "Active modes" entries are no longer
  rendered as links (regression — visual styling restored via
  ~lattice_help::with_markdown_syntax~ overlay; both peers now
  see Style::Link spans in popup.help_highlights).
- [X] Help-link follow (~<CR>~ on a link) works on TUI only.
  ~do_help_follow_link~ hoisted into ~Editor::do_help_follow_link~
  (2026-05-27); ~Action::FollowLink => BufferKind::Help~ routes to
  it. Both peers now dispatch through one host-side handler.
- [X] :terminal: in Normal mode, ~k~ doesn't move up. Root cause
  (2026-05-27): ~terminal-mode~ was registered in
  ~editor_boot.rs~ but never activated for terminal buffers, so
  ~resolve_invocation_runner~ returned None and motions fell
  through to ~run_document_invocation~ (the wrong buffer).
  Fixed by calling ~activate_major_for_buffer_kind(id,
  BufferKind::Terminal)~ in ~activate_buffer~'s Terminal arm.
- [X] Universal: cursor must never paint past the last visible
  buffer row. Resolved by the popup / terminal row-height locks
  (~popup_inner_height_rows~ derives from explicit chrome math,
  ~build_terminal_inner~ locks each row to ~estimated_row_px~,
  ~paint_pane~ uses ~pane.viewport_height~ for inactive paints).
- [X] :terminal: only half the vertical space appears used to
  render content (reported 2026-05-27 after row-lock fix). Needs
  interactive repro with ~RUST_LOG=lattice_gpui::viewport=debug~
  to confirm whether ~snap.rows~ vs ~leaf.viewport_height~ vs
  rendered pane height drift.
- [X] :b switches buffer in split → new buffer renders without
  syntax highlighting. Same root cause as terminal ~k~:
  ~resolve_invocation_runner~ was returning None for buffers
  whose major mode wasn't activated, so ~:b~ to a terminal
  buffer fell through to the document path and looked inactive.
  Resolved by the ~activate_major_for_buffer_kind~ call landed
  for terminal-mode (2026-05-27).
